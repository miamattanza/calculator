# Финансы — учёт доходов и расходов (PWA для iPhone)

Прогрессивное веб-приложение (PWA) на чистых HTML/CSS/JavaScript в нативном
iOS-оформлении. Работает офлайн, данные хранятся на устройстве в IndexedDB.
Архитектура намеренно подготовлена к переносу в полноценное приложение
(Capacitor + iCloud/CloudKit) без переписывания бизнес-логики.

## Возможности

- **Доходы и расходы** с категориями, редактированием и удалением.
- **Мультивалютность (гибридная схема):** одна основная валюта для итогов,
  у каждой операции может быть своя валюта с курсом пересчёта.
- **Аналитика:** кольцевая диаграмма по категориям и помесячная динамика.
- **Бюджеты и лимиты** по категориям с прогресс-барами и предупреждениями.
- **Прогноз остатка к дате** — ключевая функция:
  - основной расчёт: текущий баланс + плановые (регулярные/разовые) платежи
    до выбранной даты;
  - дополнительно: оценка по средним тратам за 30 дней.
- **Экспорт/импорт** данных (JSON — полный бэкап, CSV — операции).
- **Смена языка** (русский/английский) и **темы** (системная/светлая/тёмная).
- **Офлайн и установка** на домашний экран (Service Worker + manifest).

## Как запустить

PWA требует HTTP(S) (Service Worker и модули ES не работают через `file://`).
Локально достаточно любого статического сервера из корня проекта:

```bash
python3 -m http.server 8080
# или
npx serve .
```

Затем открыть `http://localhost:8080` в браузере. На iPhone: открыть адрес в
Safari → «Поделиться» → «На экран „Домой“».

## Структура проекта

```

manifest.webmanifest    — манифест PWA (иконки, имя, цвета)
service-worker.js       — офлайн-кэш app-shell
css/app.css             — оформление (iOS-стиль, светлая/тёмная тема, safe-area)
icons/                  — иконки приложения (обычные + maskable + apple-touch)
js/
  app.js                — точка входа: роутинг, таб-бар, кнопка «+»
  db.js                 — обёртка над IndexedDB (единственный слой хранения)
  store.js              — состояние и бизнес-логика (баланс, агрегаты, прогноз)
  models.js             — фабрики сущностей, категории и настройки по умолчанию
  i18n.js               — переводы (ru/en)
  format.js             — форматирование денег/дат, список валют
  dom.js                — DOM-хелперы, модальные листы, тосты, диалоги
  charts.js             — SVG-графики без внешних библиотек
  views/                — экраны (обзор, аналитика, прогноз, бюджеты, настройки)
```

## Модель данных (IndexedDB, БД `FinTrackerDB`)

- `transactions` — операции: `{id, type, amount, currency, rate, categoryId, date, note}`
- `categories` — категории: `{id, name, type, icon, color, order}`
- `planned` — плановые платежи: `{id, type, amount, currency, rate, categoryId,
  recurrence, startDate, endDate, active}`
- `budgets` — лимиты: `{id, categoryId, limit, currency, period}`
- `accounts` — зарезервировано под мультисчёт
- `settings` — настройки: `key → value`

Суммы хранятся в валюте операции + курс `rate` к основной валюте, поэтому
переход на полноценную мультивалюту не потребует миграции данных.

## Стратегия развития до нативного приложения (iCloud)

Весь доступ к данным изолирован в `js/db.js`. Бизнес-логика (`store.js`) и
представления работают только через него. Это даёт прямой путь развития:

1. **Сейчас:** PWA + IndexedDB + Service Worker (офлайн, установка на экран).
2. **Обёртка Capacitor:** тот же веб-код упаковывается в нативный iOS-проект
   (WKWebView) для публикации через App Store, без переписывания UI и логики.
3. **iCloud-синхронизация:** реализация `db.js` дополняется/заменяется
   адаптером к CloudKit или iCloud Documents (методы `getAll/get/put/remove`
   и `exportAll/importAll` уже спроектированы под снапшоты и синхронизацию).

## Тесты

Интеграционный сценарий (headless-браузер) проверяет добавление операций,
подсчёт баланса, построение диаграмм, прогноз с плановыми платежами, бюджеты
и переключение языка. Модули совместимы с проверкой `node --check`.
